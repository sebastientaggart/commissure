# Changelog

Changes to Commissure core that a solution author may need to act on. A solution author reads what it gained when upgrading a solution's `commissure` (`commissure/kit/docs/solutions.md`, Upgrade core), so an entry is written for the person updating a recipe, not for core maintainers.

- Entries go under `## Unreleased` as they land; a release renames that heading to `## <version>`.
- **Upgrading:** something a solution must change (a renamed API, a stricter check, a moved file), with the exact change to make. A core change that breaks a solution never lands without one.
- **Added:** a new capability a solution may want to adopt, such as a helper graduated to `commissure/patterns/` that replaces code in a recipe.
- History before 0.3.0 is in git.

## Unreleased

- **Upgrading:** `commissure new` also ignores `CLAUDE.local.md`, this machine's agent instructions (Claude Code loads it beside `CLAUDE.md`). In an existing solution, add `CLAUDE.local.md` to `.gitignore` beside `.claude/settings.local.json`.
- **Upgrading:** The first time this core opens a workspace for writing (`commissure run`, `commissure prune`, `commissure sources`) it applies schema migration 10 automatically: it adds `extracted_text.pruned_at`, indexes `evidence(extracted_text_id)`, and updates the `current_text` and `evidence_review` views so pruned text bodies are never read as empty text. Back up `workspace/state.db` before first use where it is the only copy of verdicts (`docs/guide.md`, "Keeping Verdicts").
- **Added:** `commissure prune [--workspace W] [--dry-run] [--vacuum] [--json]` clears the `text` and `structure` bodies (and FTS5 index entries) of superseded `extracted_text` rows that are not the newest for their `(item_version_id, parser)` and are not referenced by any `evidence` row, keeping the row, `parser_version`, `text_hash`, and parse outcome so `current_text`, `drift`, `current_outcomes`, `evidence_review`, and the verdict log remain unchanged. Pass `--vacuum` to run `VACUUM` afterwards and shrink `workspace/state.db` on disk.
- **Added:** `commissure.testing` (registered automatically as a `pytest` plugin) provides the `commissure_run` fixture and `Pipeline(workspace, recipe)` for solution tests: `.load()`, `.ingest(source, role="corpus", *flags)` (copying external folders into `tmp_path` automatically), `.parse(parser=None, *flags)`, `.stage(name, *flags)`, `.steps(*names)`, `.records(stage)` (returning current outcomes keyed by locator, group key, or `"run"` as `{outcome, reason, codes, payload}` without raw SQL), and `.review(subcommand, *args)`. Existing solutions can delete their local `CliRunner` and SQL test helpers in `tests/` and use `commissure_run` or `Pipeline` (`docs/guide.md`, "Testing a Recipe").

## 0.4.0

- **Upgrading:** A solution is now a project of its own that depends on the `commissure` package (published to PyPI), not a folder under `solutions/` in a core checkout, and its repository at a tag is its release. To move one, in its repository: run `uvx commissure==0.4.0 new /tmp/scratch-<name> --name <name>` and copy `pyproject.toml`, `AGENTS.md`, `CLAUDE.md`, and `.claude/settings.json` from it (merge any `.gitignore` lines you lack, including `.claude/settings.local.json`); then `uv sync`, `uv run commissure agent-kit` (writes core's rules, docs, and skills to `.agents/commissure/`), and `uv run ruff check --fix .` (`commissure` now sorts as a third-party import). In `recipe/AGENTS.md` and `README.md`, replace `../../AGENTS.md`, `../../.agents/skills/`, and `../../commissure/` with `.agents/commissure/`. A test that reached outside the solution (`Path(__file__).parents[2] / "tests"`) must stop. Move the solution folder as a whole, never re-clone it: `workspace/state.db` holds its verdicts, and relative folder sources keep resolving.
- **Upgrading:** `commissure init <dir>` is now `commissure new <dir>` (`--example` for a working example over a small fictional corpus). It also writes `pyproject.toml`, `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json`, `tests/test_recipe.py`, and the agent kit, and no longer writes `release.toml` or `docs/user-guide.md`.
- **Upgrading:** `commissure release` is removed, with `release.toml`, `releases/<target>.toml`, `solutions/.forbid.toml`, and the release leak scan. Release a solution by bumping `version` in its `pyproject.toml`, adding its `CHANGELOG.md` entry, running `uv run pytest`, and tagging `v<version>`; per-client values become runtime configuration. Delete `release.toml` and `releases/*.toml`, and keep any published tarballs outside the repository.
- **Added:** `commissure agent-kit [<dir>]` replaces a solution's `.agents/commissure/` (core's rules for recipe authors, `guide.md`, `solutions.md`, `architecture.md`, and the `investigate-solution` and `build-recipe-stage` skills, linked from `.claude/skills/`) with the installed version's. Run it after every core upgrade. The `new-solution` and `release-target` skills are gone: starting is one command and releasing is a tag.
- **Added:** `docs/guide.md` "Keeping Verdicts": verdicts live only in `workspace/state.db`, and backing them up is the system owner's job. Copy a live database with `sqlite3 workspace/state.db ".backup '<file>'"` (or `VACUUM INTO`), never `cp`; optionally track a `.dump` of the review tables in git as a record (never a restore path). New solutions' `docs/user-guide.md` gains a "Back up" section; an existing solution can copy it from `commissure/scaffold/template/docs/user-guide.md`.
- **Upgrading:** Folder sources inside a solution folder (`workspace/..`) are now stored in `sources.uri` as POSIX paths relative to that folder (`intake/batch`) so moving or renaming a solution folder needs no action; sources outside the solution folder remain absolute paths, and readers (`Item.source.uri`, `commissure inspect`, `commissure review`, `commissure serve`) continue to receive resolved absolute paths. A workspace created before this change that has not moved needs nothing: its next ingest rewrites each absolute source row to the relative form, keeping the source id. Run `commissure sources relocate <old solution folder> <new solution folder>` once on any workspace created before this change that has moved. If an ingest already ran at the new path and created a duplicate source, run `commissure sources relocate <old> <new> --dry-run` to inspect the colliding sources and their lineage counts, `commissure sources retire <source-id>` on the unreviewed duplicate, and then `commissure sources relocate <old> <new>`. Because `relocate` and `retire` write `workspace/state.db`, a solution that tracks its workspace in git should commit the change.
- **Upgrading:** The first time this core opens a workspace it applies schema migration 9 automatically: it rebuilds the `sources` table to add `retired_at`, keeping every row and id. Back up `workspace/state.db` before first use where it is the only copy of verdicts. `input_stale` is now wider: an outcome is stale when any outcome upstream of it, at any depth, belongs to an item version that is no longer current (changed or tombstoned), not only when a direct input was re-produced with a different result. Expect downstream group and run results to show stale after intake changes or `sources retire` until their stages rerun. `commissure review` refuses to sample a stage with stale records, so rerun downstream stages before sampling.
- **Added:** `commissure sources retire <source-id> [--workspace W] [--dry-run] [--json]` removes a duplicate or obsolete source from the current state without deleting history: it appends a tombstone `item_version` for every current item of the source in one run, sets `sources.retired_at`, and refuses when any outcome in the source's downstream lineage carries a review instance. Retired sources are never matched, adopted, or warned about by `ingest`, and never collide in `relocate`.
- **Added:** Default chart tokens, zero-JS HTML chart primitives, and Chart.js configuration in `commissure/deliver/`. `report.css` now defines `:root` chart tokens (`--chart-cat-1` to `--chart-cat-8`, `--chart-cat-rest`, `--chart-series`, `--chart-seq-1` to `--chart-seq-5`, `--chart-div-neg` / `--chart-div-mid` / `--chart-div-pos`, `--chart-wash`, `--chart-band`, `--chart-grid`, `--chart-axis-ink`, `--chart-label-on-dark`, `--chart-label-on-light`, overridable in `recipe/brand/brand.css`) and HTML chart classes (`.chart-segbar > .chart-seg`, `.chart-on-dark`, `.chart-on-light`, `.chart-legend > li > .chart-swatch`, `.chart-bars`, `.chart-canvas`, `.chart-canvas-tall`). Passing `"chart.umd.min.js"` in `render_page(..., scripts=...)` automatically includes `static/charts.js`, which applies token-backed `Chart.defaults`, colors datasets from `--chart-series` or `--chart-cat-*`, and exposes `window.CommissureCharts` (`color`, `colorFor`, `capLabels`, `referenceLines`). Recipes can delete their page-local chart palettes and Chart.js boilerplate; custom `brand.css` palettes can be validated in tests with `commissure.deliver.html.check_chart_palette`.
